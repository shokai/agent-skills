# skill-usability-test

Agent SkillやCLAUDE.md等のルール文書のように、AIが読んで従う文書のusability testを行うAgent Skillです。下位tierのmodelのsubagentにゴールを与え、検証したい文書の記述を頼りに進められるかを手を貸さずに観察します。終了後にインタビューとtranscriptの監査で判断の根拠を確かめ、文書の記述を根拠にワークフローを完遂できたかを判定します。

## 背景

skillを実装したAIエージェント自身がそのskillを使っても、配管の疎通確認にしかなりません。実装の全コンテキストを持っているため、手順書の不備に気づかず乗り越えてしまいます。

このスキルでは、ゴールだけを与えて作業を観察し、終わってから判断の根拠を聞き出す、ユーザーテストの手法を模倣します。被験者には手順書の不備を自力で補いにくい下位tierのmodelを使います。情報源は、その回で確かめたい事に応じて制限します。配布先の別のリポジトリでも文書だけで動くかを確かめる回は、実装コードやgit履歴のように手順書が無くても正解できてしまう情報源を禁止します。そのリポジトリの中で文書が働くかを確かめる回は、リポジトリ内のリソースを制限しません。検証したい機能をタスク文でほのめかさず、手順書に書いた注意点が実際に機能するかは、その罠を踏む状況を意図的に作って確かめます。

被験者の自己報告は鵜呑みにしません。作業後のインタビューで各判断の根拠を情報源ごとに分類させ、transcriptのtool呼び出し列を監査し、最終状態の実データを直接確認します。

## 使い方

```bash
/skill-usability-test [対象文書]
```

skillの手順を追加・組み替えた後や、新しいコマンドを組み込んだ後、ガイドラインの判断基準を変えた後に、「skillのusability testをして」「手順書だけで完遂できるか試して」と伝えると発動します。シナリオ案を複数提示して選んでもらい、実データを変える作業ならテストに使う環境を質問してから始めます。

Agent Skillの他に、CLAUDE.md等のルール文書と、ルール文書から参照されるリポジトリ内の文書も被験体にできます。手順書型の文書はそのまま被験体にします。ルール文書のようなガイドライン型の文書は、それが作用する作業をタスクとして与え、文書の記述が判断の根拠として使われたかを見ます。

## インストール方法

マーケットプレイスを登録してから、pluginをインストールします。

```bash
/plugin marketplace add shokai/agent-skills
/plugin install skill-usability-test
```

依存する [kuden](../kuden/README.md) も一緒にインストールされます。穴を埋めるかの判断に、kudenの共通心得と、文書の種類ごとの心得を使います。

既にマーケットプレイスを登録済みの場合、新しいスキルをインストールするには [マーケットプレイスの更新](../../README.md#スキルをうまくインストールできない場合) が必要です。

他のpluginは [リポジトリルートのREADME](../../README.md) から探せます。
