# Agent Skillを書く時の心得

Agent Skillを作成・編集する間、kuden:common-rules-for-agent-instructions skillを読み込み、その基準に加えて、以下の基準に従う。

## 心得1. 方針を書き、手段は任せる

何を確かめるか、何を達成するかを書く。どう行うかは、実行するmodelに任せる。

- どのツールのどのコマンドで行うかを、手順として指定しない。同じ操作でも、CLIで行う環境とMCPで行う環境がある。特定のコマンドを書くと、別の手段しか無い環境では成り立たなくなる
- 進め方が状況で分かれる作業に、特定のシナリオの具体例を入れない。modelが状況から判断するのをやめ、例に倣う

## 心得2. 無いとmodelが行き詰まる記述は残す

kuden:common-rules-for-agent-instructionsの「読み手は賢いmodelである」と、このskillの心得1は、具体的な記述を消す理由にならない。消す前に、その記述が無い時にmodelがどう実行するかを想像し、行き詰まるなら残す。

- 数万行あるlock fileから依存関係を調べる時の絞り込みコマンドのように、判断の助けになるヒントは残す。手順としての強制や、進め方を1つに寄せる具体例とは別の物である
- 特定のエコシステムに依存した記述を、抽象化のために先回りして消さない。他のエコシステムに対応する時に書き換えれば足りる

## 心得3. 嘘になりうる事を書かない

- 外部ツールの出力の実例を貼らない。ツールの体裁が変わると実態と食い違う。何を抜き出すかは、報告や成果物の形式例で示す
- 外部の実装に由来する列挙値を書かない。相手の実装が変わると実態と食い違う。挙動の原理と大分類までを書く。例えばファイルの埋め込みを扱うskillなら、対応する拡張子の一覧ではなく、拡張子で判定される事と、画像・動画・音声という対象の大分類を書く
- 実行時に確定できない値を、記録項目や判断の条件にしない。推定値が混ざると、記録全体が信用できなくなる

## 心得4. 手順はSKILL.mdだけに書く

skillのREADMEは人間が導入を判断するための物で、実行するmodelは読まない。modelが実行する手順はSKILL.mdだけに書き、READMEに写さない。

## 心得5. ガイドライン型のskillは、心得の並びを作業の順序に合わせる

判断基準を並べたガイドライン型のskillでは、心得の並びを、足した順ではなく、実際の作業の順序に合わせる。
